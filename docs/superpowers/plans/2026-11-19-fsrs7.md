# FSRS-7 Scheduler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add FSRS-7 as a third per-deck scheduler (`'fsrs7'`), keeping Dohrao's learning steps and whole-day review intervals.

**Architecture:** The FSRS-7 memory model is ported as pure functions into `js/fsrs.js`, next to FSRS-6. `preview()` keeps a third memory state (`stability7`, `stabilityFast7`, `difficulty7`) up to date on every answer in every mode, using fractional elapsed days. In `'fsrs7'` mode it takes review and graduation intervals from that state instead of FSRS-6's. The steps, fuzz and rounding code is shared unchanged.

**Tech Stack:** Plain ES modules, `node --test`, better-sqlite3 server (`server/sync.js`).

**Spec:** `docs/superpowers/specs/2026-11-19-fsrs7-design.md`

## Global Constraints

- Scheduler values: `'sm2'`, `'fsrs'` (default, unchanged), `'fsrs7'`. Labels: "FSRS-6", "FSRS-7 (newest)", "SM-2 (older Anki default)".
- FSRS-7 default weights, exactly (`DEFAULT_W7`, 34 values):
  `0.1104, 2.2395, 3.9221, 11.7841, 6.1686, 0.6457, 3.6807, 1.9795, 0.0, 1.3826, 0.7024, 0.5999, 0.8146, 0.6398, 1.0, 1.3207, 0.6707, 3.8668, 0.4416, 0.0934, 1.8631, 0.6162, 1.0869, 0.1567, 0.0801, 0.2421, 0.9464, 0.1433, 0.7145, 0.0, 0.5667, 0.3734, 0.5333, 0.3048`
- Bounds: S in [0.0001, 36500], D in [1, 10]; the curve's output is rescaled as `r * (1 - 2e-5) + 1e-5`.
- FSRS-7 elapsed time is fractional days: `Math.max(0, (now - lastReview) / DAY)`, with no 4am rounding.
- FSRS-7 always uses `DEFAULT_W7`. A deck's `fsrsParams` stays FSRS-6 only.
- FSRS-6 and SM-2 intervals must be identical before and after. All existing tests pass unchanged.

## Review Focus

1. **A card reviewed under FSRS-6 or SM-2 before this change**, then previewed in an `'fsrs7'` deck, must get seeded FSRS-7 memory and a sensible interval, not NaN or 0 (Task 2 test `fsrs7: an old card is seeded from its FSRS-6 memory`).
2. **A card that has reps but FSRS-6 stability 0** (old SM-2 import) must be treated as new by FSRS-7 rather than producing NaN (Task 2 test `fsrs7: a card with no FSRS-6 memory starts fresh`).
3. **Answering in an `'sm2'` or `'fsrs'` deck** must still update the FSRS-7 fields, so switching later uses a real history (Task 2 test `all three memories are kept in every mode`).
4. **Undo** must restore the FSRS-7 fields, which is covered by adding them to `newSchedule()` (Task 2 test `newSchedule includes the FSRS-7 fields`).
5. **The server must accept the new fields** and reject non-numbers (Task 3 sync test).

**Interfaces:**
- Produces, all exported from `js/fsrs.js`. A memory is `{ stability, stabilityFast, difficulty }`.
  - `DEFAULT_W7: number[]` (34)
  - `retrievability7(t: number, memory, w = DEFAULT_W7): number`. Port of `fsrs7_forgetting_curve_scalar_for_state`.
  - `nextMemory7(memory | null, g: 1..4, elapsed: number, w = DEFAULT_W7): memory`. A null memory, or one with stability 0, means a first answer: stability `w[g-1]`, difficulty `w[4] - exp(w[5]*(g-1)) + 1` (clamped), and stabilityFast `0.8 * stability`. Otherwise port `fsrs7_next_state_scalar`, clamping the inputs first as `model.rs` `step` does.
  - `nextInterval7(memory, retention = 0.9, w = DEFAULT_W7): number`. Fractional days, found by the bisection in `fsrs7_next_interval_bisection_scalar_for_state` (start with high = max(s, sFast, 1), doubling while the curve is above retention, then 50 halvings). The retention is clamped to [0.0001, 0.9999].
  - `seedMemory7(stability6: number, difficulty6: number, w = DEFAULT_W7): memory`. Port of `scale_memory_state_to_interval_scalar`, with shape `{ stability: 1, stabilityFast: 0.8, difficulty: difficulty6 }`, interval `stability6` and target retention 0.9 (bisection over log S, 50 iterations, tolerance 1e-6).

### Task 2: Schedule with FSRS-7 in `preview()`

**Files:**
- Modify: `js/fsrs.js`: `newSchedule`, `preview` (the doc comment and body)
- Test: `tests/fsrs7.test.js`

**Interfaces:**
- Consumes: the Task 1 exports.
- Produces: `preview(card, now, { scheduler: 'fsrs7', retention, fuzz, easyInterval, ... })` returns, for every rating and in every mode, the existing fields plus `stability7`, `stabilityFast7` and `difficulty7`. `newSchedule()` includes all three set to 0.

Behaviour in `preview`:
- `memory7In`: if `card.stability7 > 0`, use the card's own FSRS-7 fields; else if `card.lastReview != null && card.stability > 0`, use `seedMemory7(card.stability, card.difficulty)`; else null, meaning a first answer.
- `elapsed7 = card.lastReview == null ? 0 : Math.max(0, (now - card.lastReview) / DAY)`.
- For each g: `memory7[g] = nextMemory7(memory7In, g, elapsed7)`, and the result's `stability7`, `stabilityFast7` and `difficulty7` are set from it inside `base(g)`, in all modes.
- When `scheduler === 'fsrs7'`, `interval[g] = nextInterval7(memory7[g], retention)`. Otherwise it is unchanged. Every other branch (the `passing`, `graduateGood`, `graduateEasy` and `whole(interval[1])` restart, and the steps) is untouched and reads `interval[g]`, so it works for both FSRS modes. The `sm2` flag stays `scheduler === 'sm2'`.
